# Ролевая модель пользователей DRC

Источник: `backend/app/auth.py`, `backend/app/main.py` (`USER_ROLES`), маршруты `frontend/src/app/routes.tsx`, права в `_serialize_competence_for_user`, конструктор `NewCompetencyPage.tsx`.

Актуально на дату составления по коду репозитория.

---

## 1. Системные роли (`users.role`)

Допустимые значения: `user` | `expert` | `moderator` | `admin` | `intl_methodologist`.

| Код роли | Название | Кратко |
|---|---|---|
| `user` | Пользователь (разработчик) | Создаёт и ведёт паспорта компетенций, участвует в рабочих группах |
| `expert` | Эксперт | Проводит экспертизу назначенных компетенций |
| `moderator` | Модератор | Назначает экспертов на компетенции «на экспертизе»; **не** участвует в разработке |
| `admin` | Администратор | Полный доступ к справочникам, пользователям, стратегической сессии, имперсонации |
| `intl_methodologist` | Методист-международник | Раздел международного сопоставления (9.2 / Harmoni-BRICS), просмотр паспортов |

### Группы в коде

| Функция | Кто входит |
|---|---|
| `is_staff_role` | `admin`, `moderator`, `expert` |
| `is_moderator_role` | `admin`, `moderator` |
| `is_intl_methodologist_role` | `admin`, `intl_methodologist` |

## 2. Матрица доступа по разделам UI / API

Обозначения: **+** разрешено, **−** запрещено, **◐** ограниченно (условия ниже).

| Возможность | user | expert | moderator | admin | intl_methodologist |
|---|---|---|---|---|---|
| Публичный реестр / поиск | + | + | + | + | + |

| Мои проекты | + | + | ◐¹ | + | + |
| Создать компетенцию (`/new`) | + | + | −² | + | + |
| Реестр «В разработке» (просмотр чужих черновиков) | + | + | + | + | + |
| Стратегическая сессия | − | − | − | + | − |
| Справочник ПС / квалификации / ФГОС / ОС | − | − | − | + | − |
| Модерация / экспертиза (`/admin`) | − | + | + | + | − |
| Управление пользователями (`/admin/users`) | − | − | − | + | − |
| Обратная связь админа | − | − | − | + | − |
| Международное сопоставление (админ-раздел) | − | − | − | + | + |
| Шаг 9.2 в конструкторе компетенции | − | − | − | + | + |
| Уведомления о готовности к экспертизе | − | − | + | −³ | − |
| Имперсонация пользователей | − | − | − | + | − |

## 3. Права на компетенцию (паспорт)

### 3.1. Просмотр (`_can_view_competence`)

| Условие | Кто может смотреть |
|---|---|
| Всегда | `admin`, `intl_methodologist` |
| Лидер или принятый участник РГ | любой с ролью в РГ |
| Статус «проект» (черновик), активна | любой авторизованный (только просмотр) |
| Статус «на экспертизе» | `moderator` |
| Статус «утверждена» (в UI — «действующая») | `expert` (как публичная) |
| Назначен рецензентом | `expert` |

### 3.2. Редактирование и рабочая группа

| Действие | user (лидер) | user (участник РГ) | expert | moderator | admin | intl_methodologist |
|---|---|---|---|---|---|---|
| Редактировать черновик | + | + (только `проект`) | −⁴ | − | + | + |
| Приглашать в РГ | + (лидер) | − | − | − | + | − |
| Принимать/отклонять приглашение | + | + | + | − | + | + |
| Отправлять на валидацию / экспертизу | + (лидер, после шага 7) | − | − | − | + | − |
| Назначать экспертов | − | − | − | + | +⁵ | − |
| Проводить экспертизу (Да/Нет) | − | − | + (если назначен) | − | ◐ | − |
| Смотреть журнал активности РГ | + (лидер) | − | − | − | + | − |
| Задать срок разработки | + (лидер) | − | − | − | + | − |
| Править поля 9.2 / гармонизация | − | − | − | − | + | + |

⁴ Эксперт правит не как разработчик; доступ к карточке — как рецензент/утверждённые.  
⁵ Админ входит в `get_current_moderator` через `is_moderator_role`.

Флаги в API ответа компетенции:

| Флаг | Когда true |
|---|---|
| `can_edit` | не модератор **и** (admin \| intl_methodologist \| leader \| member при статусе `проект`) |
| `can_invite` | (admin \| leader) и статус ≠ утверждена; у модератора всегда false |
| `can_submit_review` | admin \| leader; у «чистого» intl_methodologist — false |
| `can_view_activity` | admin \| leader |
| `can_harmonize` | admin \| intl_methodologist |
| `collaboration_role` | `leader` \| `member` \| null |

## 4. Роли внутри рабочей группы (не `users.role`)

Хранятся в связке коллабораторов компетенции.

| Роль в РГ | Кто | Права |
|---|---|---|
| `leader` | Автор/руководитель группы | Полная разработка (шаги 1–7), приглашения, отправка на валидацию, срок, активность |
| `member` | Принятый участник | Правка только в статусе «проект» и только шаги 1–7; без приглашений и без отправки на экспертизу |

Модератора **нельзя** добавить в РГ (API отклоняет).

## 5. Жизненный цикл компетенции и роли

### 5.1. Статусы (БД / API)

| Статус в БД | Подпись в UI (RU) | Типичные действия |
|---|---|---|
| `проект` | Проект | Разработка лидером/участниками на шагах 1–7 (МТО) |
| `на экспертизе` | На экспертизе | Шаг 8 (валидация): модератор/админ назначает экспертов; эксперты заполняют чек-лист на карточке |
| `утверждена` | **Действующая** | После успешной экспертизы; открываются шаги 9+ конструктора; публичный реестр |
| `на доработке` / возврат в `проект` | Проект | После «Нет» экспертизы — снова зона разработки (лидер) |

### 5.2. Поток конструктора (лейблы UI)

Внутренние номера шагов: **8 = МТО (лейбл 7)**, **9 = валидация (лейбл 8)**. Константы: `DEVELOPMENT_END_STEP = 8`, `VALIDATION_STEP = 9`.

1. Разработчики (лидер и участники РГ) заполняют шаги **1–7** и **не могут** перейти дальше МТО, пока статус `проект`.
2. Руководитель на шаге 7 нажимает «Далее» → подтверждение «направить на валидацию» → статус `на экспертизе`, переход на шаг 8.
3. Модератор или администратор в `/admin` / на карточке компетенции назначают не менее трёх экспертов.
4. Назначенные эксперты проводят экспертизу (чек-лист Да/Нет) на карточке компетенции.
5. После утверждения статус в БД — `утверждена` (в UI — «действующая»); шаги **9+** конструктора разблокируются.

Участник РГ на шаге 7 кнопку отправки не видит / не может подтвердить отправку.

## 6. Сводная «одна страница»

| Роль | Главная зона ответственности | Чего нет |
|---|---|---|
| **user** | Разработка паспортов (до шага 7) и работа в РГ | Админ-справочники, назначение экспертов, 9.2 (если не intl) |
| **expert** | Экспертиза назначенных паспортов | Разработка чужих черновиков, управление пользователями |
| **moderator** | Очередь экспертизы, назначение экспертов, уведомления | Участие в РГ и любая разработка паспорта |
| **admin** | Вся система, справочники, пользователи, сессия | — (полный доступ) |
| **intl_methodologist** | Международное сопоставление / 9.2 | Управление пользователями, модерация экспертизы, создание «своих» проектов как основная роль |

## 7. Примечания по реализации

- Роль задаётся в `users.role` (строка); нормализация — `_normalize_role`.
- «Staff» на фронте (`isStaff`) = admin + moderator + expert — доступ к `/admin` (очередь экспертизы/модерации).
- Запрет модератору на разработку продублирован в UI (нет кнопки создания) и жёстко в API (403).
- Машинный доступ Plans: заголовок `X-API-Key` → служебный principal с `role=user` (без UI-ролей).
- UI-лейбл «действующая» соответствует API-статусу `утверждена` (`status.approved` в i18n).
